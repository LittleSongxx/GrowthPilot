# 入驻材料与当前卡点排查

帮助商家明确当前能准备什么、缺什么、还需核实什么。材料准备和客户自述进度不代表平台已审核通过。

## 适用与不适用

- 适用：“只有营业执照能开吗”“材料退回了该补什么”“已经注册，接下来准备什么”。
- 不适用：代提交申请、读取个人审核结果、承诺审批时间与通过，或没有原文支撑的完整首次营业操作教程。
- 配送方案、费用或优惠顾虑转到对应问题技能；不把查材料变成推销活动。

## 最少需要的信息

- 门店城市与实际经营类目；餐饮资质规则不能直接套到便利店或其他零售类目。
- 客户当前阶段：尚未准备、填写材料、提交后收到提示或已上线；只在会影响回答时询问。
- 已备材料的名称、是否齐备及页面提示原话即可；不索取证件号码、证照图片或账户验证信息。

## 判断与处理

1. 先定位客户要判断资格、准备材料还是处理提示，复用已知城市、类目和进度，不让已注册客户重走下载流程。
2. 检索当前类目的入驻要求，按原文分清主体资质、经营资质、材料和适用例外。只列检索实际支持的项目，不从常识凑一张完整清单。
3. 将原文要求与客户自述逐项对照：明确已备、明确缺项、材料适用性仍需核实。客户说“有执照”不能证明经营范围、主体或地址符合要求。
4. 明确缺项时说明该材料用于满足哪项要求，以及当前能完成的准备；如果客户问是否能用其他材料替代，只在原文明确允许且条件匹配时解释。
5. 提示退回时以客户复述的具体提示为起点，区分缺材料、信息不一致或不明原因；无实际提示时不猜退回原因，不把重新提交视为必然通过。
6. 涉及证照有效期、经营范围或主体不一致时，检索对应条款；原文没有具体阈值或处理方式就保留该未知，不能自定天数、替代证件或补交期限。不同证件各自保留原件或复印件、照片及有效期要求和允许的替代条件；不把某一证照的“原件”或有效期天数放在统领全部材料的标题下。
7. 客户愿意继续时，根据检索到的公开说明提供当前最小下一步。具体按钮、上传入口或照片要求没有依据时，先了解页面提示，不生成完整菜单路径。
8. 客户已上线再询问后续要求时，区分上线后核验与申请前材料。`meituan-merchant-video-verification-2026` 的上线后核验期限不能改写成提交申请前的门槛，也不能套到所有零售商家。
9. 没有适用品类或地区规则时，说明缺的是哪项资格依据；仍可整理客户已备材料和待核实问题，但不宣称已完成资格判定。客户更正阶段或类目后重新核对。

## 能力与证据依据

- `search_policy` 是本技能唯一业务工具：读取当前场域已入库的公开要求，不连接个人申请或审核后台。
- 来源 `meituan-merchant-faq`、`meituan-merchant-admission` 支持入驻概念与适用品类要求；`meituan-merchant-registration` 支持餐饮审查登记要求，不能跨品类外推。
- 来源 `meituan-merchant-disclosure` 支持其适用范围内的信息公示；`meituan-merchant-video-verification-2026` 支持公告所述上线后核验。是否适用仍以当次检索正文和时间条件判断。
- 来源 ID 与标题只用于定位证据，不保证此次命中，也不构成完整操作手册；客户材料和页面提示来自自述，Agent 负责对照与归纳，不产生新政策。

## 完成条件

给出原文支持的材料缺口或当前卡点、一个可执行的准备动作及仍需核实的具体条件。客户已理解下一步即可结束，不以“审核通过”或“已开店”作为本技能结果。

## 示例

- 正例：餐馆客户说“注册了，只有营业执照”。先检索餐饮入驻原文，按命中条款核对所需经营资质和其他材料，只问最影响下一步的缺项，不声称已有一张执照即可上线。
- 反例：把餐饮证照要求套给所有便利店；没有准确提示就说“退回肯定是照片模糊”；或把上线后 30 日内的视频核验说成申请前必须完成。
