# 注册、授权与借款行为辨析

## 适用与排除
- 适用：“注册是不是就借钱了”“只想了解为什么要授权”“拒绝权限还能用吗”“关闭代扣是不是不用还”。
- 目标是说明当前动作的目的、影响与选择，让客户只进行自己理解并愿意做的动作。
- 不提供个人征信查询记录、授权状态、借款状态或账户注销结果的核验；不把注册完成作为借款意愿。
- 任意链接或联系人真实性疑虑用 `financial-trust-check`；具体借款费用用 `financial-cost-explanation`。

## 最少信息
- 先确认客户想完成的功能，以及当前看到的页面标题、按钮或授权事项；已有明确描述不再重复问。
- 产品或服务主体会改变结论时才询问，例如有钱花登录、信贷服务或度小满支付授权扣款。
- 只收集不含敏感个人内容的页面文字；身份证、银行卡、验证码、密码都由客户在其确认的官方页面自行处理，不向助手提供。

## 判断顺序与分支
1. 先按目的定位动作：下载或阅读说明、账户注册登录、权限或信息授权、信用评估、借款确认、支付代扣；同一页面可能包含多项，不能仅凭一个按钮名称下结论。
2. 查当前动作对应的产品说明与政策，确认收集什么信息、用于什么功能、拒绝或撤回有什么影响；不把其他关联公司或第三方政策套过来。
3. 客户只想登录、注册、看账单或了解安全时，保持该信息用途。查询返回 `product_kind=app_information` 或 `supports_cost_estimate=false` 时，不换成融资方案继续推介。
4. “注册是否等于借款”：解释账户建立与申请、签署借款相关协议分别属于什么行为；只能根据已明确的动作解释，不能据此断言客户账户里不存在借款申请、授信或借款；没有完整流程依据时，不概括为“必须签署某协议才进入审批”的统一顺序。
5. “为什么要实名或绑卡”：先确认是否已进入信贷或支付服务，再按该服务原文解释用途；不能把信贷服务的实名要求说成仅阅读说明也必须完成。
6. “是否会查征信”：确认当前是否涉及信用评估以及具体授权文字；注册、摄像头权限或通讯录权限都不能单独证明已经或不会查询征信。
7. “拒绝权限能否用”：区分该权限与哪项功能有关，再说明原文中的拒绝影响；不能概括为“全都必须同意”或“全部拒绝也不影响”。
8. 客户想撤回授权时，先确认授权类别；仅当检索到对应产品的准确路径时指导最小下一步，页面不一致就回到客户看到的文字，不猜菜单。
9. 代扣授权涉及支付协议时，说明授权主体、范围及终止条款；停止某项扣款授权不能被解释为免除已经存在的还款义务，也不能假定所有借款都启用了代扣。
10. 客户仅愿意了解、不愿意授权时，停留在可回答的信息层；不建议为了演示、看额度或领取权益而先提交申请。
11. 条款残缺或页面含义不明时，指出还需要哪段不含个人信息的文字，再解释已确认部分；不让客户“先点下一步看看”。
12. 客户更正产品或动作后，撤回不适用的解释并重新判断，不沿用先前产品的权限、合同或状态结论。

## 完成与停止条件
- 完成：客户能分清当前动作、相关用途和拒绝或继续的影响，并自行决定是否继续；注册、申请、借款分别决策。
- 客户已明确只阅读、暂缓或拒绝时停止操作引导；需要个人账户结果时明确现有能力不能核验。
- 对话中不代填敏感资料、不请求授权凭证，不声称已经关闭权限、注册成功或撤回授权。

## 正例与反例
- 正例：客户说“只是注册，为什么要银行卡”。先确认页面和目标，查相应政策；若文字指向信贷实名或支付服务，解释这与账户登录的区别，客户只想了解就停在说明层。
- 反例：“绑卡只是注册步骤，放心点同意，不会有任何后果。”这是在未确定服务和授权内容时作保证。

## 能力与证据登记
- 工具：`query_product_options` 确认信息用途与能力边界；`search_policy` 提供信息收集、拒绝影响及授权条款；Agent 对照目的与动作进行分诊。
- 已登记来源：`dxm-credit-privacy`（登录、信贷实名、权限与撤回）、`dxm-payment-debit-authorization`（特定支付扣款授权）、`dxm-official-credit-faq`（公开申请和审批说明）。
- 本地目录：`catalog_app_registration`、`catalog_app_login`、`catalog_information_safety` 等信息说明，不提供账户状态，也不是完整的 App 操作指南。
- 来源 ID 仅登记采集依据，不表示已建库或当次命中；政策路径、日期及适用范围只以工具本次返回正文为据。
- 运行时通过已开放工具取证，不读取本地参考文件，也不依赖屏幕观察或个人账户接口。
