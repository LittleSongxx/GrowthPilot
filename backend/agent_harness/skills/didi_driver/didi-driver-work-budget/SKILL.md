# 兼职投入与收支预算

## 适用与排除
- 解决“只跑周末租车划不划算”“一天流水就是赚到的吗”“每月得收到多少才能覆盖成本”等问题。
- 没有收入数据也可以算成本和收入门槛；不能把工具中的车费参数外推成订单量、日流水或月收入。
- 准入条件和租赁期限冲突分别使用对应 SOP；本 Skill 不替客户选择职业或承诺收益。

## 最少需要的条件
- 客户确认的月出车天数、月固定经营支出、出车日平均变动成本和可退押金金额；已知为零才填零。
- 只有要算收支差额时才需要月收入假设，口径必须是扣平台费用后、扣经营成本前的金额。
- 当客户问当地计费或需要租车数据时再确认城市、业务类型及用车条件，不为纯计算重复收集信息。

## 判断顺序与分支
1. 先判断客户是在解释收入概念、比较固定投入，还是已经有一组条件要试算，避免一上来要求填满数字。
2. 客户提到“流水、到账、赚到”时先问清金额口径。已扣平台费用的到账金额不再次扣费；乘客支付额不能直接当收入。
3. 只需计费解释时，按返回参数解释计价组成及未包含费用，到此即可；不能由起步价和公里费虚构平均单价。
4. 需要预算时，将月租等归入月固定支出，电油费等归入出车日变动成本；同一项目只计一次，未知费用单列。
5. 押金仅在金额和可退性质已确认时作为可退押金输入；不能因目录叫“押金”就假定无条件全退，未知不填零。
6. 出车天数、固定支出和变动成本均由客户确认。兼职天数少时，解释固定支出分摊会升高，不靠假定增加出车天数改善结果。
7. 条件齐全后确定性计算；月收入未知时只给经营成本、月收入门槛和日均收入门槛，不补造收入来算“赚多少”。
8. 有月收入假设时给出条件收支差额。客户调整天数或成本后重新计算；奖励只有已明确并确认计入才进入收入假设。
9. 将全月经营成本加押金说明为首月现金预算，不称签约当天应付款；客户若问当天支付额，须另有付款时间条款。

## 完成与停止条件
- 交付收入口径、已纳入成本、仍缺项目，以及有依据的试算或收入门槛；少成本项时称“已知成本范围内的预算”，不称净利润。
- 预算结论可以是当前固定投入负担较高、需要补充成本或暂不选择该方案；客户愿意才继续讨论用车或注册。
- 核心数字未知时先解决口径并只追问影响当前计算的一项，不编数字；客户不愿提供或暂缓时结束。

## 能力与证据依据
- `query_driver_earnings` 仅返回本地车费及平台服务费参考；`search_car_rentals` 支撑可查租赁成本，两者来源为 `growth-agent-catalog-v1`，非实时个人收入或合同。
- `estimate_work_budget(work_days, monthly_fixed_cost, daily_variable_cost, refundable_deposit, monthly_income=None)` 承担确认条件后的计算；出车天数为 1—31 天，月收入可以缺省，四个必填条件不能用未知值替代。
- 工具返回经营成本、月及日均收入门槛、首月现金预算和可选收支差额；费用单位为元，结果仍依赖输入口径与覆盖范围。
- `search_policy` 可查 `didi-algorithm-explanation` 的适用品类和非固定派单机制，以及 `didi-national-driver-rights` 的透明计价要求；监管要求不是每名司机的固定抽成或已获福利。
- 所有政策说明以当次实际检索正文为据；来源 ID 不是调用参数，不用历史统计填充客户的收入假设。

## 例子
- 正例：客户确认每月跑 8 天、固定支出 3600 元、每出车日变动成本 80 元、可退押金 6000 元，收入未知。计算已知月经营成本 4240 元、日均收入门槛 530 元、首月现金预算 10240 元，并说明这不证明能达到门槛。
- 反例：客户只说“北京快车，周末跑”。不能从起步价估计每天 20 单后承诺月入，也不能把未知电费填零；先解释现有数据能回答的计费口径和固定投入问题。
