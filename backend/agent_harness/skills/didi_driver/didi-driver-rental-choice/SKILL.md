# 租车方案与试跑期限匹配

## 适用与排除
- 解决“只想试一个月能不能租”“月租便宜是否适合我”“电车和油车怎么选”等租赁决策。
- 已发生的合同争议、事故赔偿或垫付款返还不属于租车选择；客户单独询问公开规则时，应按该问题另行解释适用原文，不能插入当前方案比较。
- 判断能否覆盖租车成本使用收支预算 SOP；租车目录不是车辆准入、实时库存或成交保证。

## 最少需要的条件
- 接单城市、预计持续租多久、可承受的首期现金及是否已有明确能源类型偏好。
- 仅在影响方案选择时补问出车频率、补能条件、可接受的里程限制；城市信息足以先查，不强求详细地址。
- 区分客户愿意承担的条件与目录返回的参考假设，不把参考假设写成客户偏好。

## 判断顺序与分支
1. 先看是否存在已知人车准入障碍；准入尚未核实时可以比较租赁条件，但不能据此建议直接签约。
2. 将客户试跑期限与每份方案的最短租期先对齐。期限冲突时优先指出，不用低月租掩盖更长承诺。最低租期匹配不证明合同只有该期限或没有续租、提前通知和退出限制。
3. 分开比较月租等持续支出和押金等现金占用；未知退还条件的押金不能直接当成最终可退，也不全算月度费用。
4. 按实际返回内容整理包含项、排除项与未知项，尤其是保险、营运资质、维修、里程和能源费用。
5. 预算不足时说明被哪项限制；期限不匹配时指出当前没有符合条件的方案，客户愿意后再比较更长租期或其他选项。
6. 比较电车和油车时结合客户实际补能条件；没有里程与能耗依据就不推算谁每月一定更省。
7. 客户询问候选方案的退租、保险或维修条款时，先看该方案实际已给出的包含项和排除项；合同缺项直接标为待核实，不为填满清单继续检索通用纠纷规则。没有这份合同适用的依据，不引用取消订单退押、事故折旧、年检或理赔垫付款返还时限来补齐候选方案。当前只比较租期、已列费用与合同缺项，不另讲平台纠纷处理规则。
8. 回答合同缺项时先给当前结论，再按提前退租、保险、维修这几类客户实际问到的事项，分别用一句话列出已知项与待核项。客户没有要求的事故计算和垫付规则不展开，不把通用条款写成合同全文。若另行解释适用规则，必须同时保留责任主体与归责前提、触发事件、金额基数、时限起算及例外；无法完整保留时不单独报补偿比例或时限。
9. 参考方案或范围估算保留其适用条件；租金、地址或电话以本次返回为准，不承诺最近、现车或可立即办理。

## 完成与停止条件
- 输出符合条件的候选及原因，或明确说明当前候选为何不匹配；保留足以影响签约决策的未知项。
- 下一步聚焦一个实际缺口，例如确认短租选项或补齐退租条款；不把“去问客服”作为比较工作的全部结果。
- 客户只需了解、暂缓或拒绝时结束；尚不能确认条款时停在条件比较，不确认合同责任或代客户签约。

## 能力与证据依据
- `search_car_rentals` 提供本地方案，依据为返回记录、价格口径和有效期；`growth-agent-catalog-v1` 是本地版本化业务来源，非官方实时报价。
- `search_policy` 支撑准入与租赁规则解释；使用实际返回的正文、范围与版本，来源 ID 不是工具参数。
- `didi-driver-admission` 解释平台注册条件；地方人车条件按准入 SOP 中真实可检索的地方规则核对。
- `didi-rental-dispute-rules` 是特定受理范围的纠纷规则，不是候选车辆的保险单、维修合同或主动退租报价；当前租车选择不以它补全目录缺项。
- 工具未返回的解约责任、库存和保险细项都仍是未知；不要求模型读取合同文件或查询未开放的业务接口。

## 例子
- 正例：客户只想租一个月，返回方案最短租期三个月。先指出期限不匹配，再说明月租、押金与未知退租条款；不因低月租推荐签约。
- 反例：客户问“提前退一定扣多少钱”。不能用月租乘剩余月数当作违约金，也不能说押金一定全退；须保留实际合同条款缺口。
