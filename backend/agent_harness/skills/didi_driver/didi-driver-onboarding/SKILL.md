# 报名材料与公开起步准备

## 适用与排除
- 解决“要先准备什么”“已经安装还需要做什么”“注册和驾驶员证是什么关系”等阶段与材料疑问。
- 是否符合人车条件使用准入 SOP；租车及收入顾虑先解决，不用下载流程绕开顾虑。
- 不承接实时账户状态、未接到首单原因、订单异常处置或代办注册审核。

## 最少需要的条件
- 接单城市、业务类型和客户自述阶段：未准备、准备资料、已安装、已提交、已通过某项审核。
- 指导具体步骤时确认客户看到的提示；不要求客户提供完整证件、验证码或账户凭据。
- 区分平台注册、驾驶员资格与车辆许可，不把客户说“办好了”自动理解为三者都已完成。

## 判断顺序与分支
1. 先用一句话对齐客户已做的事项和当前目标，已安装或已提交就从当前阶段开始，不重走开头。客户尚未安装且愿意接收下载短信时，调用 `send_download_sms` 发送当前场景的 App 下载链接，依据返回结果说明发送是否成功。
2. 准备阶段按本次适用原文列必要资料与资格事项，区分需要已有证件和后续办理的事项，保留城市及业务范围。
3. 客户缺少某项时，只说明该缺项影响哪一步及有证据的补齐路径；材料齐全不等于资格满足或审核通过。
4. 客户问资料用途或授权时，依据实际隐私条款解释对应目的；操作便利不能替代客户对授权的选择。
5. 已提交但未完成时，先分清缺材料、页面问题和未知审核状态；根据客户提示与公开说明给出一步操作，不猜退回原因。
6. 只有检索到对应业务与页面的路径才能指导具体操作；缺乏路径时交付已确认的材料及阶段说明，不编按钮名称。
7. 客户自述已获资格或注册完成时，核对其想准备的事项，解释有依据的资质、车辆、安全服务等公开要求；不确认已可接单。
8. 客户需要线下协助时，按所在地查询服务点是否提供相应事项；城市级可先查，不能根据服务名称推断现场可办证。

## 完成与停止条件
- 客户清楚当前阶段、尚缺事项及一个可执行的下一步即可结束；不以获取个人资料或完成首单作为本 Skill 的完成标准。
- 可交付的清单应来自原文和客户自述，不把“所有问题转客服”替代已有资料可以解决的准备工作。
- 操作路径缺失、实时状态未知时停在已确认范围；客户完成只按其自述衔接，拒绝或暂缓时不继续推进。

## 能力与证据依据
- `search_policy` 提供条款和公开办理说明；必须阅读本次返回正文及适用范围，来源 ID 仅用于核对出处。
- `send_download_sms` 向当前客户发送司机 App 下载短信；发送成功仅表示短信已发送，下载和注册进度仍以客户自述为准。
- `didi-driver-admission`、`didi-national-driver-qualification` 支撑基础资格与材料；`didi-driver-privacy` 支撑个人信息用途解释。
- `didi-fuzhou-rules-2023` 支撑福州适用资格要求；办理指南 `didi-fuzhou-driver-licensing` 尚未成功收录，不依赖它提供报名、考试或查询的具体路径。后续只有实际检索到该指南正文才可使用，其中行政核发不收费不能扩大为任何培训或相关服务都免费。
- `didi-xiamen-electronic-driver-certificate`、`didi-xiamen-vehicle-permit-smart-application-2025` 只适用于对应厦门证照及运输证办理，不是滴滴 App 注册流程。
- `didi-xiamen-driver-licensing-and-cost-response-2025` 是历史答复，不能承诺当前排期；`didi-national-operation-rules` 可支持公开运营准备要求。
- `search_driver_service_points` 的业务记录来源为 `growth-agent-catalog-v1`，只介绍实际返回的服务范围、地址和电话，不推断距离、接待时间或代办权限。

## 例子
- 正例：福州客户说“App 装好了，还没有驾驶员资格证”。根据适用原文解释平台注册与从业资格的区别，列出已知资格准备事项；未取得当地办理指南时不猜报名入口，不要求重新下载。
- 反例：客户说“注册了但没接到第一单”。不能声称审核未通过、教点不存在的接单按钮或保证接单；说明工具无法查个人接单状态，仅解决其明确的公开准备问题。
