# 城市、人、车准入条件梳理

## 适用与排除
- 解决“有驾照能不能跑”“外地牌照能不能用”“换城市还要核对什么”等准入疑问。
- 已提交材料后的操作问题使用报名准备 SOP；租车价格和收入问题先保留，不混成准入判断。
- 目标是明确已有条件、明确缺项和待核实项，不作个人准入、车辆合规或审批通过的结论。

## 最少需要的条件
- 接单城市、咨询业务类型，以及当前关注的是驾驶员、车辆还是两者；已有信息不重复问。
- 只在对应条款影响结论时，询问驾龄、车辆登记情况等必要条件，不收集证件号码、照片或敏感记录明细。
- 暂无车辆时先处理驾驶员条件，车辆部分列出后续选车要核对的标准，不要求客户编造车型。

## 判断顺序与分支
1. 先确定接单城市。居住地不自动等于接单城市；客户改城市时重新检查当地规则，不沿用原结论。
2. 分开看全国基础条件、平台注册要求、地方条件。检索到某一层不能宣称已覆盖全部条件。
3. 驾驶员与车辆分别核对：把客户自述与本次检索到的适用条款逐项对应，保留条款中的例外和生效范围。
4. 有明确不匹配条件时，说明是哪条、哪项不符及仍可补齐什么；不为推动注册跳过该条件。
5. 缺的是材料时转为准备清单；缺的是资格或车辆条件时说明需先解决的事项，不能把上传材料视为已满足条件。
6. 福州、杭州只使用检索到的本地适用正文；杭州车辆新车要求与原文例外分别判断，不只摘取其中一句。
7. 厦门现有资料可以解释证照及部分办理问题，不能据其推导完整驾驶员、车辆准入标准。
8. 其他城市若没有本地正文，先交付全国及平台层面可确认的基础清单，明确尚缺的地方核对项，不借用邻市规则。

## 完成与停止条件
- 用“已知符合描述的条件、明确缺项、仍待核实项”归纳当前问题；客户自述只说明对照情况。
- 给出一个与缺项相符的下一步；客户只问条件时不强行接续下载、注册。
- 来源冲突、过期或地区不适用时，不作该项判断；客户不愿继续提供必要条件或拒绝时停止推进。

## 能力与证据依据
- `search_policy` 提供实际条款；来源 ID 用于识别出处，不是调用参数。必须看当次正文与范围，目录存在不等于已检索成功。
- 基础依据：`didi-driver-admission`、`didi-national-operation-rules`、`didi-national-driver-qualification`。
- 地方依据：`didi-fuzhou-rules-2023`、`didi-hangzhou-rules-2023`、`didi-hangzhou-vehicle-technical-standard-2023`；逐项核对实际返回内容，不推断未检索到的户籍或居住条件。
- `didi-fuzhou-driver-licensing` 当前因官网访问限制未收录，不能作为办理路径依据；福州基础条件只使用实际已入库的实施细则。
- 厦门局部依据：`didi-xiamen-electronic-driver-certificate`、`didi-xiamen-driver-licensing-and-cost-response-2025`；不补造缺失的地方条件。
- 业务目录覆盖城市与政策覆盖城市独立；租车目录中的方案不能充当人车准入证明。

## 例子
- 正例：客户说“我准备在杭州跑快车，有一辆旧车”。先确认车辆登记背景，再依据杭州规则区分一般要求与例外，交付已知条件和待核对事项。
- 反例：客户说“北京，有驾照也有车”。不能套用杭州轴距或福州驾龄条件，更不能回答“肯定能注册”；先解释可证实的基础要求及北京地方规则缺口。
