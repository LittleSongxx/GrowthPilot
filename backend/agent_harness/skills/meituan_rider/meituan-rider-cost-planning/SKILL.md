# 起步投入与收益条件测算

## 适用与边界

- 解决“按这些出勤与成本条件，收入需要达到什么水平、预计能剩多少”。
- 以条件测算帮助比较投入，不预测实际单量，不承诺工资、奖励或收入稳定性。
- 只想选租赁方案时使用租赁比较技能；不知道配送模式时先澄清与计酬有关的类型。

## 最少信息

- 解释当地计酬需要城市和明确配送类型；查到的参考单价不能自动变成个人月收入。
- 计算需要客户确认的月出勤天数、每月固定支出、每个出勤日变动成本和可退押金；月收入假设可选，口径为已扣平台费用、未扣经营成本。
- 月收入假设不是必答项：客户不知道或不愿估计时，保留未知，不替其猜单量。
- 费用为零也需有依据或客户确认；未提到电费、装备等不等于这些成本为零。

## 判断与推进

1. 先问清“赚多少”指配送收入、到账还是扣除运营成本后的金额；月收入输入统一为已扣平台费用、未扣经营成本，同一笔费用不重复扣。
2. 将计酬依据分成基础配送报酬、满足条件才有的奖励、未包含的个人费用。参考区间保持原有适用范围，不能拿最高值代表所有订单。
3. 有车与租车分开处理。租车月租属于固定支出，可退押金属于现金占用；电池、换电、维修是否包含以已返回方案或客户条款为准。
4. 把已知费用归入月固定支出或出勤日变动成本，检查有无重复计入。只确认会影响本次算账的缺项，不收集无关报名资料。
5. 客户愿意算且输入充分时，用 `estimate_work_budget` 得到确定性结果；结果与收入假设一同说明，称为“这些条件下扣除已列成本的余额”，不称净利润或保证到手。全月成本加押金是首月现金预算，不等于签约当天应付金额。
6. 月收入未知但成本、出勤已确认时，只计算覆盖已列成本所需的月收入及日均门槛；这不是预测日流水，也不说明实际可以达到。
7. 成本也不完整时，先交付收入与成本结构、指出决定结论的缺项；不把缺项补零后输出一个看似完整的收益数。
8. 客户减少出勤时，重新分摊固定支出。若已知固定投入与试跑计划不匹配，可建议先缩小投入或比较短租，不能默认用更多跑单解决。
9. 客户更正金额或改变方案时，更新对应输入并重算；保留仍适用的假设，撤回旧结果。

## 完成与停止

- 完成：交付已列成本、计算假设、月度余额或成本门槛，以及尚未计入的项目；让客户自行决定是否接受投入。
- 资料不足时完成已知成本结构和补充清单，不给收入预测；客户只想了解计酬时解释完即结束。
- 未确认的奖励、订单量、退租损失不进入确定性结果；不推动超时出勤以追求预设收益。

## 正反例

- 正例：客户知道月租和每月能跑几天，却不知道收入。确认其他成本后只算覆盖成本的门槛，并说明还不能回答最终能剩多少。
- 反例：取目录最高单价，假设每天固定接单，再把押金当月支出，得出“每月稳赚这个数”。单量和费用口径均无依据。

## 能力依据

- `search_policy`：已配置来源 `meituan-rider-pricing`、`meituan-rider-faq`，用于解释计酬构成与适用条件。
- `query_delivery_pay`、`search_vehicle_rentals`：提供目录中的计酬和租赁参考条件，不提供真实个人单量或最终合同。
- `estimate_work_budget`：按客户确认条件计算月收支与成本门槛，独立展示可退押金的现金占用；不生成收入假设。
- Agent 负责费用归类、口径校对和缺项识别；以当次返回数据为依据，来源已配置不等于本次已检索成功。
