# 保障顾虑与适用条件解释

## 适用与边界

- 解决“跑单有哪些保障”“宣传中的保障是否覆盖我担心的情况”的理解问题。
- 目标是分清保障类型与可证实的条件；不办理参保、判定事故责任或核算个人理赔。
- 已发生事故的紧急处置、诊疗及争议代理不属于本技能；只解释与问题相关且有原文依据的信息。

## 最少信息

- 客户关心的是跑单职业伤害、养老等社保补贴，还是本人或家人疾病支出。
- 原文要求地区、骑手类型、跑单状态或保障对象时，再询问会改变解释的条件。
- 不索取身份证号、病历、诊断细节或账户截图；客户自述只能用于条件对照，不能证明资格。

## 判断与推进

1. 先把“有保险吗”拆成客户担心的风险与对应保障类别；不了解差异时简短说明三类目的不同，不混用报销、补贴和职业伤害待遇。
2. 依据对应保障的当次原文，整理谁适用、覆盖什么、有哪些条件、哪些细节没有披露；没有原文的项目不写成权益清单。
3. 职业伤害保障先核对发布日期和地区范围。旧公告的试点省份与后续全国覆盖披露属于不同时间，不能拼成同一时点结论。
4. 对覆盖披露，只解释其政策范围；“全国覆盖”“每单必保”等表述不能推导为报名即已参保、任何事故都赔或个人申请必定通过。原文未给出个人参保起止条件时，不添加“先完成一单才参保”等门槛；订单状态和材料准备不能推断个人保障是否生效。
5. 社保补贴先分清“缴纳社保”和“满足补贴条件”两件事；不把政策上线、历史发放案例当成当前客户已经满足条件或即将到账。
6. 大病关怀保留稳定跑单、保障对象、地区、疾病范围及费用条件等原文明示限制；概括宣传不能覆盖具体条款，案例金额不成为客户待遇。
7. 客户问“那我能赔多少”时，先解释当前已知覆盖与个人赔付的区别，再明确尚缺实际适用规则和资格认定；不根据新闻金额反推个人赔款。
8. 原文存在适用条件但客户还不确定时，形成具体核实事项，如跑单资格定义或适用计划；有可靠渠道说明才能提供，不编造 App 菜单或统一理赔材料。客户想报名前弄清保障时，优先给报名前可咨询的渠道与核对事项，不把先报名或先跑单设为了解规则的前提。

## 完成与停止

- 完成：客户知道正在谈哪类保障、原文支持到哪一步、哪些条件影响自身适用及哪些问题仍需具体规则。
- 有明确资料即可解答保障概念与条件，不把整项问题直接推给客服；个人参保和赔付结论则停止推断。
- 客户只是了解风险时，解释完即结束，不把“有保障”当作催促报名的理由。

## 正反例

- 正例：客户问“有保障是不是摔伤都能赔”。解释职业伤害保障的公开覆盖说明，同时保留事故认定、保险期间和实际待遇规则，不输出确定赔付结论。
- 反例：“新闻说覆盖全国，所以您注册后全部意外都能报销，家人看病也一样。”这把不同计划、资格和保障范围混成一个承诺。
