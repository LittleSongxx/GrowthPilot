# 业务资料维护

项目有两类业务输入：政策 RAG 默认使用随 Git 发布的固定教学语料 `backend/agent_harness/rag/knowledge/v1/`，业务查询使用本地版本化目录。二者分别维护，查询结果保留各自的来源和适用范围。教学语料包含四场景的 42 份整理正文和 1285 个分块，与评测冻结语料一致；固定知识输入不保证模型回答逐字相同。

## 政策证据

[知识来源目录](../backend/agent_harness/rag/sources.yaml)包含骑手招募 FAQ、商家入驻 FAQ、司机相关规则、地方规定、有钱花官网 FAQ，以及特定银行的合同条款。回答以当次 `search_policy` 实际返回的正文为依据。

资料的用途不能互相替代：FAQ 只支持所述问题，地方规定保留城市范围，历史公告保留时间范围，特定资方合同不能推出统一利率。标题、人工整理的适用提醒和搜索命中本身不是政策结论。

当前需要持续核对的内容包括：

- 不同城市的司机和车辆准入、注册材料、审核时限以及实际 App 操作路径。
- 骑手装备、租赁、退款和保障的完整适用条件。
- 商家当前费率、合同方案、证照续期和店铺运营步骤。
- 金融产品的年龄条件、材料、还款路径和特定资方费用条款。

公共资料不能给出个人审批、额度、实际收入或到账保证；缺少适用正文时应继续检索或说明缺口。当前索引版本与资料规模通过 `growthpilot knowledge status` 查看，数量不作为问答准确率。教学语料保留冻结时的资料，不随启动自动更新为最新政策。

## 地区服务与方案数据

[业务目录](../backend/agent_harness/business_data/README.md)提供站点、计酬、租赁、商家方案、产品说明和费用计算。它由精细记录、城市配置和通用方案组成，可按输入地区生成稳定结果，尚未接入品牌实时站点、报价和活动接口。

原始条件、实际采用条件、版本和有效期随查询保留。通用方案扩大可查询范围，但不补写官方政策，也不核实个人资格。更换数据源时应替换对应查询适配器，并继续保留这些字段。

## 增加或更新资料

先确定具体客户问题和适用范围，再收集能回答该问题的原文。每份资料至少记录：

| 信息 | 要求 |
| --- | --- |
| 业务问题 | 客户需要判断或执行什么 |
| 发布主体与来源 | 可验证机构、原文 URL 或获授权的受控资料 |
| 原文定位 | 章节、页码或完整问答，不能仅提供摘要 |
| 适用范围 | 城市、业务类型、产品、资方、渠道和合同版本 |
| 时间与版本 | 公布、生效、失效和最近核验日期；抓取日期不是生效日期 |
| 费用与条件 | 保留计费前提、参与资格、限制、例外和未包含项目 |
| 仍未知事项 | 明确原文未覆盖的部分 |

人工复核完整前提、有效性及来源冲突后，按 [RAG 增加资料流程](../backend/agent_harness/rag/README.md#增加或更新资料)更新 `sources.yaml`，使用 `growthpilot knowledge build --refresh` 显式采集并检查原文、分块与具体问题的查询结果。结果写入 `.run/knowledge/`，不会自动改写固定教学语料；`--from-cache` 可复用上次采集的分块，两者互斥。下次 `growthpilot up` 会恢复固定教学版本。

发布新教学版本时，将审阅后的正文、分块、来源元数据与文件哈希作为同一版本维护，并同步评测语料及标注。文件中的项目路径只使用相对路径或以 `/growthpilot` 开头的项目路径，不写入本机用户目录。个人资料不放入公共政策索引；客户自述通过 Memory 保存。

站点目录、价格与活动可接入获授权的实际数据源。仅增加文字说明或修改 Skill 不会自动获得接口能力；接入后还需要对应适配器、权限和回归验证。
